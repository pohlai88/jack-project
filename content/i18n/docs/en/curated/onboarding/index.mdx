## Thesis

Docs quality comes from governed evidence, not editor discipline.

## Model

The pipeline is deterministic:

1. Update the implementation.
2. Update the relevant feature manifest, contract, route, API definition, permission surface, or error taxonomy.
3. Regenerate docs evidence.
4. Review generated output.
5. Commit implementation and evidence together.

## Operational implication

To add or update documentation evidence, update the product truth source beside the implementation first.

Then run:

```bash
pnpm docs:generate
```

Commit the generated documentation evidence with the implementation change.
