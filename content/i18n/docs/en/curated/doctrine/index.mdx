## Thesis

Documentation is not a narrative. It is the outward projection of governed product truth.

## Model

Afenda documentation is an evidence surface generated from governed product truth. Manual prose may explain that truth, but it cannot redefine it.

## Operational implication

A documentation page is release-worthy only when it can be traced back to one of the following sources:

- a feature manifest
- a workflow definition
- an API contract
- a permission contract
- an error taxonomy
- a troubleshooting record
- a governed doctrine, ADR, or ATC

If the source of truth is missing, the page must be treated as explanatory context, not authoritative evidence.

## Model

- Generated evidence outranks narrative prose.
- Route, API, permission, and error surfaces must remain deterministic.
- Documentation must expose what the system proves, not what the team remembers.
- Stale generated evidence is a release risk, not a formatting issue.
